***Administrando o Banco de Dados***

As primeiras coisas que devem ser observadas são:

***Versões do SQL Server***<br>
O banco de dados escolhido pela empresa foi o SQL Server. Sendo assim, a primeira missão é escolher a versão do SQL Server que será utilizada.

***Requisitos do sistema***<br>
É preciso garantir que o hardware e o sistema operacional sejam compatíveis com a versão escolhida.

***Funcionalidades necessárias***<br>
Cada versão oferece um conjunto diferente de recursos e funcionalidades, é preciso escolher o que mais se adéqua ao seu ambiente de negócios.

***Licenciamento***<br>
O SQL possui diferentes opções, incluindo licenças por núcleo ou por servidor.

***Escalabilidade***<br>
É necessário que o SQL escolhido tenha possibilidade de ser escalável, já que ele espera que o uso do banco de dados cresça ao longo do tempo.

***Suporte***<br>
É preciso entender o tipo de suporte oferecido por cada versão do SQL Server.

***Segurança***<br>
Dependendo da versão escolhida, Marcos terá acesso a recursos mais ou menos avançados de segurança.

***On premise ou nuvem***<br>
Por fim, o profissional precisa decidir onde instalar o SQL Server. Podendo ser um premisse, ou seja, no servidor da empresa ou em nuvem.<br>
Essa decisão é fundamental, afinal, se ele optar por uma instalação em nuvem, muitas atividades exercidas serão repassadas pelo administrador da nuvem, como o backup ou administração do espaço físico das bases de dados.

Porém, além dessas escolhas, existem tipos diferentes de edições. Sendo: <br>

***Enterprise Edition***<br>
Essa edição oferece recursos avançados de autodesempenho e segurança. É muito utilizado por empresas corporativas.

***Standard Edition***<br>
Oferece recursos básicos de gerenciamento de banco de dados, relatórios, integrações e análises de dados. É voltada para empresas de pequeno e médio porte.

***Express Edition***<br>
Essa é uma edição gratuita, ideal para desenvolvedores e organizações que precisam de uma plataforma de banco de dados básica para aplicativos de pequeno porte.

***Developer Edition***<br>
Uma versão mais completa, projetada exclusivamente para desenvolvimento e teste.

***Funções de um DBA***<br>

Vamos entender as funções exercidas por um DBA:

***Instalação e configuração do banco de dados***<br>
Após a instalação é necessário realizar a configuração, definir a política de crescimento e determinar onde fisicamente o banco de dados será gravado.

***Monitoramento do desempenho***<br>
O DBA precisa monitorar continuamente o desempenho do banco para poder identificar possíveis gargalos e problemas de desempenho.<br>
Também é preciso otimizar o banco, reorganizar a estrutura, ajustando algumas configurações e assim trazer melhorias.

***Gerenciamento de segurança***<br>
Devemos garantir que o banco de dados esteja protegido contra acessos não autorizados, roubo de dados e outras ameaças.<br>
É preciso estabelecer políticas e procedimentos de segurança, gerenciar as contas dos usuários e aplicar as permissões adequadas.

***Realização de backups e recuperação de dados***<br>
Realizar backups periódicos do banco de dados para garantir a integridade destes é essencial. Em casos de falha, é preciso ter uma recuperação rápida.

***Gerenciamento da capacidade do banco de dados***<br>
Outra função muito importante é o monitoramento do crescimento do banco ao longo do tempo. A partir disso é possível avaliar se será necessário adicionar mais hardware ao ambiente ou utilizar a estrutura do banco de dados para suportar o tamanho dos arquivos físicos.

***Gerenciando a base de dados***<br>

Vamos entender como funciona o gerenciamento de uma base de dados:

***Requisitos da base de dados***<br>
Apesar do pouco tempo de trabalho, já lhe foi passado um desafio: a necessidade de criar uma base de dados para suportar um sistema de vendas que a empresa vai implementar.

Essa base de dados deve ser criada suportando uma série de características:

- A base de dados e de log devem estar em diretórios diferentes;
- Tamanho inicial será de 100 MB;
- Tamanho máximo dos arquivos será de 200 MB;
- Taxa de crescimento será de 50 MB.

Já estamos logados no Management Studio com o usuário sa e senha que determinamos na instalação do SQL Server. Agora, podemos clicar no botão "Nova Consulta" na barra de ferramentas (ou atalho "Ctrl + N").<br
Com isso, abre-se a janela de consulta à direita do painel "Pesquisador de Objetos". Nela, vamos colar o seguinte comando para criar a base de dados:<br>

![image](https://github.com/user-attachments/assets/511b1332-292d-4e6f-b19c-a76f0213fca0)

Explicando cada linha do comando: <br>

***1 -*** Começamos pelo comando `CREATE DATABASE` para criar a base de dados; <br>
***2 -*** Colocamos um nome lógico para o banco de dados como um todo. Nesse caso, o banco de dados será reconhecido pelo `SQL Server` pelo nome dbVendas; <br>
***3 -*** Depois, temos dois blocos de comandos. Um se inicia com `ON PRIMARY` e serve para criar a base de dados onde os dados serão salvos; <br>
***4 -*** O outro se inicia com `LOG ON` para criar o log de transações; <br>
***5 -*** o parâmetro `NAME` define um nome lógico somente para aquele componente da base de dados; <br>
***6 -*** O nome lógico dos dados é `dbVendas` em caracteres Unicode, enquanto do log de transações é `dbVendasLOG` também em caracteres Unicode; <br>
***7 -*** Colocamos o caminho e o nome do arquivo físico que vai ficar gravado dentro do disco através do parâmetro `FILENAME`; <br>
***8 -*** Para os dados, colocamos o caminho até a pasta `"ARQUIVO_DADOS > dbVendas.MDF"` onde a base de dados deve ser salva; <br>
***9 -*** Ao passo que o log ficará salvo na pasta "`LOG_TRANSACOES > dbVendasLOG.LDF`"; <br>
***OBS:***  a extensão do arquivo de dados deve ser `.MDF` e, para o arquivo de log, .`LDF`; <br>
***10 -*** Além disso, definimos o tamanho inicial da base de dados com o parâmetro `SIZE`. Colocamos 100MB tanto para o arquivo de dados quanto para o de log de transações; <br>
***11 -*** Também especificamos o tamanho máximo como 200MB para o componente de dados e log de transações. Para isso, usamos o parâmetro `MAXSIZE`; <br>
***12 -*** Por último, limitamos a taxa de crescimento para 50MB em ambos com o parâmetro `FILEGROWTH`. <br>

***Otimizar a base de dados***<br>
Nessa consulta, vamos copiar o seguinte comando:<br>

`DBCC SHRINKDATABASE ('dbVendas',TRUNCATEONLY);`<br>

Lembre-se que atualmente o arquivo de log de transações está com `204MB` de tamanho e temos `3229 notas fiscais` na base de dados.<br>
Primeiro, vamos selecionar e executar o comando `DBCC SHRINKDATABASE()` seguido do nome da base e o parâmetro `TRUNCATEONLY`.<br>
Se verificamos novamente o tamanho do arquivo `dbVendasLOG.LDF`, note que a base reduziu para `102MB`. Porém, não perdemos dados.

Continuamos com as mesmas 3290 notas fiscais. Por que isso aconteceu? O comando SHRINKDATABASE reduz a base de dados. Os dados reduzidos são devolvidos para o sistema operacional para usá-los para outros fins.<br>

É como se fosse um comando defrag no disco. Quando utilizamos o disco para armazenar dados, seja porque estamos editando um arquivo comum ou um arquivo físico do banco de dados, os blocos de memórias vão ser gravados dentro do disco em uma sequência.<br>

Cada vez que essa bloco de memória grava dados, o arquivo cresce. À medida que excluímos ou alteramos dados dentro desse arquivo, vão ficando blocos de memória vazios na área reservada do disco.
Em outras palavras, internamente existem blocos que não são mais usados, mas que ainda contam para o tamanho do arquivo, deixando-o maior.<br>

No momento em que executamos o comando defrag, esses blocos de memória são retirados do arquivo e não contam mais para seu tamanho. Desse modo, são liberados para o sistema operacional. Com isso, o arquivo reduz o tamanho sem perder dados.<br>
